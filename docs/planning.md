# 기획서 — DACON 해커톤 대시보드

---

## 1️⃣ 서비스 개요

| 항목 | 내용 |
|---|---|
| **서비스명** | DACON Hackathon Hub |
| **한줄 소개** | 해커톤 탐색부터 팀 빌딩, 제출, 순위 확인까지 한곳에서 완결하는 해커톤 통합 대시보드 |
| **개발 목표** | 이전 개발자가 남긴 기능 명세서(memo.png)와 UI 흐름도(Hackathon-UI-Flow.png)를 충실히 구현하고, UX 확장 아이디어를 더해 완성도 높은 웹서비스를 Vercel에 배포한다 |

### 타겟 사용자
- **해커톤 참가자**: 진행 중인 대회를 탐색하고, 팀을 구성하며, 결과물을 제출하는 개인/팀
- **해커톤 운영자/심사자**: 제출 현황과 리더보드를 통해 참가팀의 성과를 확인하는 관계자
- **관심 있는 예비 참가자**: 해커톤 일정·상금·평가 기준을 비교하고 팀원 모집 글을 탐색하는 잠재 참여자

### 기대효과
- **정보 탐색 비용 절감**: 해커톤 목록 → 상세 → 제출 → 순위를 하나의 흐름으로 연결하여, 여러 페이지를 오가는 수고를 제거
- **팀 빌딩 허들 완화**: 해커톤별 팀원 모집 게시판(Camp)으로 역할·연락처를 한눈에 파악
- **제출 실수 방지**: 해커톤 유형(zip / text+url+pdf)에 맞는 단계별 제출 UI 제공
- **실시간 경쟁 동기 부여**: 리더보드를 통해 순위를 즉시 확인하고 개선 동기를 얻음

## 2️⃣ 페이지 구성

### 페이지 목록 및 연결 관계

```
메인페이지 (/)
  ├─→ 해커톤 목록 (/hackathons)
  │       └─→ 해커톤 상세 (/hackathons/:slug)
  │             ├── [탭] 개요 · 평가 · 일정 · 상금 · 안내 · 팀 · 제출 · 리더보드
  │             ├─→ 팀원 모집 (/camp?hackathon=:slug)
  │             └─→ 리더보드 (제출 시 자동 업데이트)
  ├─→ 팀원 모집 (/camp)
  └─→ 랭킹 (/rankings)
```

### 페이지별 상세

#### (1) 메인페이지 — `/`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 로고, 글로벌 검색바, 해커톤 카드 미리보기(최대 3개), 팀 모집 미리보기, 랭킹 미리보기 |
| **입력/버튼/메뉴** | 검색바(키워드 입력), 해커톤 카드 클릭, "전체 보기" 링크, 상단 네비게이션(메인·해커톤·캠프·랭킹) |
| **가능한 행동** | 키워드로 해커톤 검색, 카드 클릭 시 `/hackathons/:slug`로 이동, 각 섹션의 "더보기"로 목록 페이지 이동 |

#### (2) 해커톤 목록 — `/hackathons`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 해커톤 카드 리스트(썸네일, 제목, 상태 배지, 태그, 마감일), 필터/정렬 컨트롤 |
| **입력/버튼/메뉴** | 상태 필터(진행중/종료/예정), 태그 필터(복수 선택), 정렬(최신순/마감임박순), 키워드 검색 |
| **가능한 행동** | 필터 조합으로 목록 필터링, 카드 클릭 시 상세 페이지 이동. 결과 없으면 빈 상태 UI 표시 |

#### (3) 해커톤 상세 — `/hackathons/:slug`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 해커톤 제목·상태·기간 헤더, 8개 탭 섹션 콘텐츠 |
| **입력/버튼/메뉴** | 탭 네비게이션(개요·평가·일정·상금·안내·팀·제출·리더보드) |
| **가능한 행동** | 탭 전환으로 섹션 탐색, 팀 탭에서 캠프 이동, 제출 탭에서 파일 업로드·저장·제출, 리더보드 탭에서 순위 확인 |

**탭 상세:**

| 탭 | 데이터 소스 | 핵심 내용 |
|---|---|---|
| 개요 | `detail.sections.overview` | 요약 설명, 팀 정책(솔로 가능 여부, 최대 인원) |
| 평가 | `detail.sections.eval` | 평가 지표명, 설명, 점수 가중치(참가자 30% / 심사위원 70%), 제한사항 |
| 일정 | `detail.sections.schedule` | 타임라인 형태로 마일스톤 표시 (접수→제출 마감→투표→결과 발표) |
| 상금 | `detail.sections.prize` | 순위별 상금 테이블 (1st/2nd/3rd + 금액) |
| 안내 | `detail.sections.info` | 공지사항 목록, 규정·FAQ 외부 링크 |
| 팀 | `detail.sections.teams` + `public_teams.json` | 해당 해커톤 소속 팀 목록, "팀 만들기" 버튼 → `/camp`, `hackathonSlug`로 필터 |
| 제출 | `detail.sections.submit` | 해커톤 유형별 제출 UI — `submissionItems`에 따라 단계별(기획서→웹링크→PDF) 또는 단일(zip) 제출 |
| 리더보드 | `public_leaderboard.json` | 순위 테이블(등수·팀명·점수·제출일), 점수 breakdown 표시, 제출 시 자동 갱신 |

#### (4) 팀원 모집 — `/camp`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 팀 카드 리스트(팀명, 해커톤명, 인원, 모집 역할, 소개, 모집 상태 배지) |
| **입력/버튼/메뉴** | 해커톤별 필터(`?hackathon=:slug`), "팀 만들기" 버튼(팀명·소개·연락처·정원 입력 폼) |
| **가능한 행동** | 해커톤별 필터링, 팀 카드에서 연락처(오픈카카오/구글폼) 확인, 새 팀 생성 후 localStorage 저장 |

#### (5) 랭킹 — `/rankings`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 전체 해커톤 통합 랭킹 테이블(순위·팀명·점수/포인트), 기간 필터 |
| **입력/버튼/메뉴** | 기간 필터(전체/월별/연도별), 해커톤 선택 드롭다운 |
| **가능한 행동** | 기간별·해커톤별 필터로 랭킹 조회, 팀 클릭 시 상세 정보 확인 |

### 공통 레이아웃
- **네비게이션 바**: 모든 페이지 상단에 고정 — 로고 + 메뉴(메인, 해커톤, 캠프, 랭킹)
- **반응형 디자인**: 모바일(≤768px)에서 햄버거 메뉴, 카드 1열 배치 / 데스크톱에서 2~3열 그리드

## 3️⃣ 시스템 구성

### 기술 스택

| 계층 | 기술 | 선택 이유 |
|---|---|---|
| **프레임워크** | Next.js 14+ (App Router) | 파일 기반 라우팅, SSR/SSG 지원, Vercel 네이티브 배포 |
| **언어** | TypeScript (strict) | 타입 안전성, JSON 시드 데이터 스키마 검증 |
| **스타일링** | Tailwind CSS | 유틸리티 기반 빠른 UI 구현, 반응형 용이 |
| **데이터 저장** | localStorage | 외부 DB/API 키 없이 심사 가능, JSON 시드로 초기화 |
| **배포** | Vercel | 대회 필수 요구사항, Next.js 최적 호환 |

### 데이터 흐름

```
1. 최초 접속
   └─ localStorage 비어있음 → data/*.json에서 시드 데이터 로드
      ├─ public_hackathons.json      → localStorage["hackathons"]
      ├─ public_hackathon_detail.json → localStorage["hackathonDetails"]
      │   (extraDetails[] 펼쳐서 slug별로 정규화)
      ├─ public_leaderboard.json     → localStorage["leaderboards"]
      │   (extraLeaderboards[] 펼쳐서 slug별로 정규화)
      └─ public_teams.json           → localStorage["teams"]

2. 이후 접속
   └─ localStorage에 데이터 존재 → 시드 건너뜀 → 기존 데이터 사용

3. 사용자 액션
   ├─ 팀 생성 → localStorage["teams"]에 추가
   ├─ 제출 저장 → localStorage["submissions"]에 저장 (임시)
   ├─ 제출 확정 → localStorage["submissions"] 업데이트 + localStorage["leaderboards"] 갱신
   └─ 모든 변경은 페이지 새로고침 후에도 유지
```

### 핵심 데이터 파싱 주의사항
- `public_hackathon_detail.json`: `daker-handover-2026-03` 상세는 `aimers` 객체의 `extraDetails[]` 안에 중첩되어 있음 → 파싱 시 펼쳐서 slug 기준으로 정규화해야 함
- `public_leaderboard.json`: 동일하게 `extraLeaderboards[]`에 핸드오버 해커톤 리더보드가 중첩 → slug별로 분리 필요
- 해커톤별 제출 타입이 다름: aimers는 `zip`, handover는 `text/url/pdf` 3단계 → `allowedArtifactTypes`와 `submissionItems` 기반으로 동적 UI 렌더링

## 4️⃣ 핵심 기능 명세

### F1. 해커톤 목록 필터링 및 정렬

| 항목 | 내용 |
|---|---|
| **입력** | 상태 필터(진행중/종료/예정), 태그 필터(복수 선택), 정렬 기준(최신순/마감임박순), 키워드 검색 |
| **동작** | `localStorage["hackathons"]` 배열을 조건에 맞게 필터 → 정렬 → 렌더링. 키워드는 title, tags에서 부분 매칭 |
| **결과** | 조건에 맞는 해커톤 카드만 표시. 결과 0건이면 "조건에 맞는 해커톤이 없습니다" 빈 상태 UI |

### F2. 해커톤 상세 탭 네비게이션

| 항목 | 내용 |
|---|---|
| **입력** | 탭 클릭 (개요/평가/일정/상금/안내/팀/제출/리더보드) |
| **동작** | URL slug로 `hackathonDetails[slug]`를 조회, 선택된 탭의 섹션 데이터를 렌더링 |
| **결과** | 탭별 콘텐츠 전환 — 개요는 텍스트, 일정은 타임라인, 상금은 테이블, 제출은 폼, 리더보드는 순위표 |

### F3. 단계별 제출 시스템

| 항목 | 내용 |
|---|---|
| **입력** | 해커톤 유형에 따라: (a) zip 파일 업로드 또는 (b) 기획서(텍스트/URL) → 웹링크(URL) → PDF(파일) 단계별 입력 + 선택적 메모(notes) |
| **동작** | `submissionItems` 배열 기반으로 동적 폼 생성. "저장" → localStorage에 임시 저장. "제출" → 제출 확정 + 리더보드 엔트리 생성 |
| **결과** | 제출 완료 시 제출 상태 표시(제출됨/임시저장), 리더보드에 팀 엔트리 추가, 재접속 시 제출 이력 유지 |

### F4. 리더보드 표시 및 자동 갱신

| 항목 | 내용 |
|---|---|
| **입력** | 해커톤 상세 페이지의 리더보드 탭 진입, 또는 제출 완료 이벤트 |
| **동작** | `localStorage["leaderboards"]`에서 해당 `hackathonSlug`의 엔트리를 조회, score 내림차순 정렬 |
| **결과** | 순위 테이블 렌더링 (등수, 팀명, 점수, 제출일). 점수 breakdown이 있으면 참가자/심사위원 점수 분리 표시. 엔트리 없으면 "아직 제출된 결과가 없습니다" 빈 상태 |

### F5. 팀원 모집 (Camp)

| 항목 | 내용 |
|---|---|
| **입력** | 팀 만들기: 팀명, 소개, 연락처(URL), 모집 역할, 해커톤 선택. 필터: 해커톤별 |
| **동작** | 새 팀 생성 시 teamCode 자동 생성 → `localStorage["teams"]`에 추가. 목록은 `hackathonSlug`로 필터링 |
| **결과** | 팀 카드 리스트 표시 (팀명, 해커톤, 인원, 모집 역할, 소개, 모집중/마감 배지). 연락처 클릭 시 외부 링크 이동 |

### F6. 통합 랭킹

| 항목 | 내용 |
|---|---|
| **입력** | 기간 필터(전체/월별/연도별), 해커톤 선택 |
| **동작** | 모든 `leaderboards` 엔트리를 합산/필터하여 통합 순위 계산 |
| **결과** | 랭킹 테이블 (순위, 팀명, 점수/포인트). 필터 변경 시 즉시 재계산 |

### F7. 글로벌 검색

| 항목 | 내용 |
|---|---|
| **입력** | 상단 검색바에 키워드 입력 |
| **동작** | 해커톤 제목, 태그, 팀명 등에서 부분 매칭 검색 |
| **결과** | 매칭 결과를 카테고리별로 그룹핑하여 드롭다운 표시, 클릭 시 해당 페이지로 이동 |

## 5️⃣ 주요 사용 흐름

### 흐름 A: 해커톤 탐색 → 참가

```
1. 메인페이지(/) 접속
   └─ 해커톤 카드 미리보기 확인

2. "전체 보기" 클릭 → /hackathons 이동
   └─ 상태: "진행중" 필터 선택
   └─ 관심 해커톤 카드 클릭

3. 해커톤 상세 (/hackathons/:slug) 진입
   ├─ [개요] 탭: 대회 설명 및 팀 정책 확인
   ├─ [평가] 탭: 평가 기준·가중치 확인
   ├─ [일정] 탭: 마감일 타임라인 확인
   └─ [상금] 탭: 상금 구조 확인

4. [팀] 탭 → "팀원 모집 보기" 클릭 → /camp?hackathon=:slug
   └─ 관심 팀 연락처 확인 또는 "팀 만들기"
```

### 흐름 B: 결과물 제출

```
1. 해커톤 상세 → [제출] 탭 진입

2. (handover 해커톤의 경우)
   ├─ Step 1: 기획서 입력 (텍스트 또는 URL) → "저장"
   ├─ Step 2: 최종 웹링크 입력 (URL) → "저장"
   └─ Step 3: 솔루션 PDF 업로드 → "저장"

3. 모든 항목 입력 완료 → "제출" 버튼 활성화 → 클릭

4. 제출 확정
   ├─ 제출 상태: "제출됨" 배지 표시
   └─ 리더보드에 엔트리 자동 추가

5. [리더보드] 탭에서 본인 팀 순위 확인
```

### 흐름 C: 팀 생성 및 모집

```
1. /camp 접속 또는 해커톤 상세 [팀] 탭에서 이동

2. "팀 만들기" 버튼 클릭
   └─ 폼 입력: 팀명, 소개, 연락처 URL, 모집 역할(Frontend/Backend/Designer/...), 해커톤 선택

3. "생성" 클릭 → localStorage에 저장 → 팀 카드 목록에 즉시 반영

4. 다른 사용자: 팀 카드에서 연락처 클릭 → 외부 링크(오픈카카오/구글폼)로 이동
```

### 예외 상황 처리

| 상황 | 화면 처리 |
|---|---|
| **검색 결과 없음** | "검색 결과가 없습니다" + 검색어 초기화 버튼 |
| **필터 결과 없음** | "조건에 맞는 해커톤이 없습니다" + 필터 초기화 안내 |
