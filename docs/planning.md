# 기획서 — DACON 해커톤 대시보드

---

## 1️⃣ 서비스 개요

| 항목 | 내용 |
|---|---|
| **서비스명** | DACON Hackathon Hub |
| **한줄 소개** | 해커톤 탐색부터 팀 빌딩, 제출, 순위 확인까지 한곳에서 완결하는 해커톤 통합 대시보드 |
| **개발 목표** | 이전 개발자가 남긴 기능 명세서(memo.png)와 UI 흐름도(Hackathon-UI-Flow.png)를 충실히 구현하고, UX 확장 아이디어를 더해 완성도 높은 웹서비스를 Vercel에 배포한다 |

### 타겟 사용자
- **해커톤 참가자**: 진행 중인 대회를 탐색하고, 팀을 구성하며, 결과물을 제출하는 개인/팀
- **해커톤 운영자/심사자**: 제출 현황과 리더보드를 통해 참가팀의 성과를 확인하는 관계자
- **관심 있는 예비 참가자**: 해커톤 일정·상금·평가 기준을 비교하고 팀원 모집 글을 탐색하는 잠재 참여자

### 기대효과
- **정보 탐색 비용 절감**: 해커톤 목록 → 상세 → 제출 → 순위를 하나의 흐름으로 연결하여, 여러 페이지를 오가는 수고를 제거
- **팀 빌딩 허들 완화**: 해커톤별 팀원 모집 게시판(Camp)으로 역할·연락처를 한눈에 파악
- **제출 실수 방지**: 해커톤 유형(zip / text+url+pdf)에 맞는 단계별 제출 UI 제공
- **실시간 경쟁 동기 부여**: 리더보드를 통해 순위를 즉시 확인하고 개선 동기를 얻음

## 2️⃣ 페이지 구성

### 페이지 목록 및 연결 관계

```
메인페이지 (/)
  ├─→ 해커톤 목록 (/hackathons)       ← 큰 카드 버튼 "해커톤 보러가기"
  │       └─→ 해커톤 상세 (/hackathons/:slug)   ← 카드 클릭
  │             ├── [탭] 개요/안내 · 평가 · 일정 · 상금 · 팀 · 제출 · 리더보드 (7개)
  │             ├── 제출(Submit) ──저장/제출──→ 리더보드 업데이트
  │             └── 팀 탭 ──"이 해커톤 팀 보기/생성"──→ /camp?hackathon=:slug
  ├─→ 팀원 모집 (/camp)               ← 큰 카드 버튼 "팀 찾기"
  └─→ 랭킹 (/rankings)               ← 큰 카드 버튼 "랭킹 보기"
```

### 공통 요구사항 (모든 페이지)

| 항목 | 내용 |
|---|---|
| **상단 네비게이션 바** | 메인(`/`) · 해커톤(`/hackathons`) · 캠프(`/camp`) · 랭킹(`/rankings`) 이동 링크. 확실한 라우팅만 담당 |
| **3종 상태 UI (필수)** | 모든 데이터 영역에 **로딩중…** / **데이터 없음** / **에러** 상태를 반드시 표시 |
| **공개 금지 원칙** | 내부 유저 정보, 유저가 비공개한 정보, 다른 팀의 내부 정보는 절대 노출하지 않음 |

### 페이지별 상세

#### (1) 메인페이지 — `/`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | **큰 카드 버튼 3개** — 각각 해커톤/팀/랭킹 페이지로의 진입점 역할 |
| **입력/버튼/메뉴** | ① "해커톤 보러가기" → `/hackathons` ② "팀 찾기" → `/camp` ③ "랭킹 보기" → `/rankings` |
| **가능한 행동** | 카드 버튼 클릭으로 각 섹션 페이지 이동 |

#### (2) 해커톤 목록 — `/hackathons`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 해커톤 리스트 — 각 항목에 **제목, 상태(진행중/종료), 태그, 시작일, 종료일, 참가자 수** 표시 |
| **입력/버튼/메뉴** | 카드 클릭 → `/hackathons/:slug` 이동 |
| **가능한 행동** | 목록 탐색, 카드 클릭으로 상세 이동 |
| **(옵션) 필터** | 상태 필터(진행중/종료), 태그 필터 — 구현 시 우선순위 낮음 |

#### (3) 해커톤 상세 — `/hackathons/:slug` ★핵심 페이지
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 해커톤 제목·상태·기간 헤더 + **7개 필수 섹션** 탭 콘텐츠 |
| **입력/버튼/메뉴** | 탭 네비게이션 (개요/안내 · 평가 · 일정 · 상금 · 팀 · 제출 · 리더보드) |
| **가능한 행동** | 탭 전환, 팀 초대/수락/거절, 제출 폼 작성·저장·제출, 리더보드 확인 |

**7개 필수 섹션 상세:**

| 탭 | 데이터 소스 | 핵심 내용 |
|---|---|---|
| **개요/안내** | `sections.overview` + `sections.info` | 대회 요약 설명, 팀 정책(솔로 가능 여부, 최대 인원), 공지사항 목록, 규정·FAQ 외부 링크 |
| **평가** | `sections.eval` | 평가 지표명, 설명, 점수 산출 방식 — 투표(participant 30% + judge 70%) 또는 평가 산식에 따라 동적 표시 |
| **일정** | `sections.schedule` | 타임라인 형태로 마일스톤 표시 (접수→제출 마감→투표→결과 발표) |
| **상금** | `sections.prize` | 순위별 상금 테이블 (1st/2nd/3rd + 금액) |
| **팀** | `sections.teams` + `public_teams.json` | 해당 해커톤 팀 목록 + **초대/수락/거절 버튼**. "이 해커톤 팀 보기/생성" → `/camp?hackathon=:slug` 이동 |
| **제출** | `sections.submit` | 제출 가이드 표시 + 제출 폼: 메모(notes, optional) + 파일 업로드(zip/pdf/csv 등 해커톤 설정에 따라 동적). `submissionItems`가 있으면 단계별(기획서→웹링크→PDF) |
| **리더보드** | `public_leaderboard.json` | 순위 테이블(등수·팀명·점수·제출일). 점수 기준은 해커톤 설정(투표/평가 산식)에 따라 계산. **참여했으나 미제출 시 "미제출" 표기 (순위 없음)** |

**(옵션)** 팀 구성 시 유의사항 팝업

#### (4) 팀원 모집 — `/camp`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 팀 카드 리스트 (팀명, 해커톤명, 인원, 모집 역할, 소개, 모집중/마감 배지) |
| **입력/버튼/메뉴** | "팀 모집글 생성" 버튼, 해커톤 필터(`?hackathon=:slug`) |
| **가능한 행동** | 목록 조회(쿼리 필터), 팀 생성, 연락처 확인 |

**팀 생성 폼 필드:**

| 필드 | 필수 여부 | 설명 |
|---|---|---|
| 팀명 | **필수** | 팀 이름 |
| 소개 | **필수** | 팀 소개글 |
| 모집중 여부 (isOpen) | **필수** | 모집 상태 토글 |
| 모집 포지션 (lookingFor[]) | 선택 | Frontend, Backend, Designer 등 복수 선택 |
| 연락 링크 (contact.url) | 선택 | 오픈카카오톡 / 구글 폼 등 URL |
| 해커톤 연결 | **선택** | 해커톤과 연결하지 않아도 팀 생성 가능. 해커톤 상세에서 생성 시 자동 연결 |

**(옵션)** 모집글 수정 / 모집마감 처리, 채팅·쪽지 보내기

#### (5) 랭킹 — `/rankings`
| 구성 요소 | 설명 |
|---|---|
| **보여주는 것** | 글로벌 랭킹 테이블 — **rank / 닉네임 / points** |

| **가능한 행동** | 해커톤 전체 참여·순위·기록에 대한 유저별 랭킹 조회 |

## 3️⃣ 시스템 구성

### 기술 스택

| 계층 | 기술 | 선택 이유 |
|---|---|---|
| **프레임워크** | Next.js 14+ (App Router) | 파일 기반 라우팅, SSR/SSG 지원, Vercel 네이티브 배포 |
| **언어** | TypeScript (strict) | 타입 안전성, JSON 시드 데이터 스키마 검증 |
| **스타일링** | Tailwind CSS | 유틸리티 기반 빠른 UI 구현, 반응형 용이 |
| **데이터 저장** | localStorage | 외부 DB/API 키 없이 심사 가능, JSON 시드로 초기화 |
| **배포** | Vercel | 대회 필수 요구사항, Next.js 최적 호환 |

### 데이터 흐름

```
1. 최초 접속
   └─ localStorage 비어있음 → data/*.json에서 시드 데이터 로드
      ├─ public_hackathons.json      → localStorage["hackathons"]
      ├─ public_hackathon_detail.json → localStorage["hackathonDetails"]
      │   (extraDetails[] 펼쳐서 slug별로 정규화)
      ├─ public_leaderboard.json     → localStorage["leaderboards"]
      │   (extraLeaderboards[] 펼쳐서 slug별로 정규화)
      └─ public_teams.json           → localStorage["teams"]

2. 이후 접속
   └─ localStorage에 데이터 존재 → 시드 건너뜀 → 기존 데이터 사용

3. 사용자 액션
   ├─ 팀 생성 → localStorage["teams"]에 추가
   ├─ 팀 초대/수락/거절 → localStorage["teams"] 멤버 상태 업데이트
   ├─ 제출 저장 → localStorage["submissions"]에 저장 (임시)
   ├─ 제출 확정 → localStorage["submissions"] 업데이트 + localStorage["leaderboards"] 갱신
   └─ 모든 변경은 페이지 새로고침 후에도 유지
```

### 핵심 데이터 파싱 주의사항
- `public_hackathon_detail.json`: `daker-handover-2026-03` 상세는 `aimers` 객체의 `extraDetails[]` 안에 중첩 → 파싱 시 펼쳐서 slug별 정규화
- `public_leaderboard.json`: 동일하게 `extraLeaderboards[]`에 핸드오버 리더보드 중첩 → slug별 분리
- 해커톤별 제출 타입 상이: aimers는 `zip` 단일 업로드, handover는 `text/url/pdf` 3단계 → `allowedArtifactTypes`와 `submissionItems` 기반 동적 UI
- 점수 계산 방식 상이: aimers는 `FinalScore`(성능+속도), handover는 `vote`(참가자 30% + 심사위원 70%) → `scoreSource` 필드로 분기

### 개인정보 보호 원칙
- **내부 유저 정보**: 시스템 내부 식별자, 이메일 등 절대 노출 금지
- **비공개 설정 정보**: 유저가 비공개로 설정한 정보 노출 금지
- **타 팀 내부 정보**: 다른 팀의 제출물 내용, 내부 논의 등 노출 금지

## 4️⃣ 핵심 기능 명세

### F1. 해커톤 목록 표시 및 탐색

| 항목 | 내용 |
|---|---|
| **입력** | `/hackathons` 페이지 진입 |
| **동작** | `localStorage["hackathons"]` 배열을 읽어 리스트 렌더링. 각 항목에 제목, 상태(진행중/종료), 태그, 시작일, 종료일, 참가자 수 표시 |
| **결과** | 해커톤 리스트 표시. 카드 클릭 시 `/hackathons/:slug`로 이동. 데이터 없으면 "데이터 없음" 상태 표시 |

### F2. 해커톤 목록 필터 (옵션)

| 항목 | 내용 |
|---|---|
| **입력** | 상태 필터(진행중/종료), 태그 필터(복수 선택) |
| **동작** | 선택된 조건으로 목록 필터링 |
| **결과** | 조건에 맞는 항목만 표시. 결과 0건이면 "데이터 없음" UI |

### F3. 해커톤 상세 7개 필수 섹션

| 항목 | 내용 |
|---|---|
| **입력** | 탭 클릭 (개요/안내 · 평가 · 일정 · 상금 · 팀 · 제출 · 리더보드) |
| **동작** | URL slug로 `hackathonDetails[slug]`를 조회, 선택된 탭의 섹션 데이터 렌더링 |
| **결과** | 탭별 콘텐츠 전환 — 개요/안내는 요약+공지, 일정은 타임라인, 상금은 테이블, 제출은 폼, 리더보드는 순위표 |

### F4. 팀 관리 (초대/수락/거절)

| 항목 | 내용 |
|---|---|
| **입력** | 해커톤 상세 [팀] 탭에서 초대 버튼 클릭, 수락/거절 버튼 클릭 |
| **동작** | 초대: 대상 유저에게 팀 초대 요청 생성 → localStorage 저장. 수락: 팀 멤버로 추가. 거절: 초대 삭제 |
| **결과** | 팀 구성 상태 업데이트. 팀 멤버 목록에 반영. "이 해커톤 팀 보기/생성" 링크로 `/camp?hackathon=:slug` 이동 가능 |

### F5. 제출 시스템

| 항목 | 내용 |
|---|---|
| **입력** | 제출 가이드 확인 후 폼 작성: 메모(notes, optional) + 파일 업로드. 파일 형식은 해커톤 설정에 따라 zip/pdf/csv 등. handover 해커톤은 `submissionItems` 기반 단계별(기획서→웹링크→PDF) |
| **동작** | "저장" → localStorage["submissions"]에 임시 저장. "제출" → 제출 확정 + 리더보드 엔트리 생성/갱신 |
| **결과** | 제출 상태 표시(제출됨/임시저장). 리더보드에 팀 엔트리 추가. 재접속 시 이력 유지 |

### F6. 리더보드

| 항목 | 내용 |
|---|---|
| **입력** | 해커톤 상세 [리더보드] 탭 진입, 또는 제출 완료 이벤트 |
| **동작** | `localStorage["leaderboards"]`에서 해당 `hackathonSlug` 엔트리 조회, 해커톤 설정(투표/평가 산식)에 따라 점수 계산, score 내림차순 정렬 |
| **결과** | 순위 테이블 (등수, 팀명, 점수, 제출일). 점수 breakdown 있으면 분리 표시. **참여했으나 미제출 시 "미제출" 표기 (순위 부여하지 않음)**. 엔트리 없으면 "데이터 없음" 상태 |

### F7. 팀원 모집 (Camp)

| 항목 | 내용 |
|---|---|
| **입력** | 팀 모집글 생성: 팀명(필수), 소개(필수), 모집중 여부(isOpen), 모집 포지션(lookingFor[]), 연락 링크(contact.url). **해커톤 연결은 선택** — 연결 없이도 생성 가능 |
| **동작** | teamCode 자동 생성 → `localStorage["teams"]` 추가. 목록은 `?hackathon=:slug` 쿼리로 필터링. 해커톤 상세 [팀] 탭에서 생성 시 자동 연결 |
| **결과** | 팀 카드 리스트 (팀명, 해커톤, 인원, 모집역할, 소개, 모집중/마감 배지). 연락처 클릭 시 외부 링크 이동 |

### F8. 글로벌 랭킹

| 항목 | 내용 |
|---|---|
| **입력** | `/rankings` 페이지 진입 |
| **동작** | 모든 해커톤의 참여·순위·기록을 통합하여 유저별 랭킹 계산 |
| **결과** | 글로벌 랭킹 테이블 (rank / 닉네임 / points). **(옵션)** 기간 필터: 최근 7일 / 30일 / 전체 |

## 5️⃣ 주요 사용 흐름

### 흐름 A: 해커톤 탐색 → 정보 확인

```
1. 메인페이지(/) 접속
   └─ "해커톤 보러가기" 큰 카드 버튼 클릭

2. /hackathons 이동
   └─ 해커톤 리스트 탐색 (제목, 상태, 태그, 기간, 참가자 수)
   └─ 관심 해커톤 카드 클릭

3. 해커톤 상세 (/hackathons/:slug) 진입
   ├─ [개요/안내] 탭: 대회 설명, 팀 정책, 공지사항, 규정 링크
   ├─ [평가] 탭: 평가 기준·가중치 확인
   ├─ [일정] 탭: 마감일 타임라인 확인
   └─ [상금] 탭: 상금 구조 확인
```

### 흐름 B: 팀 빌딩

```
1. 해커톤 상세 → [팀] 탭 진입
   ├─ 기존 팀 목록 확인
   ├─ 초대 버튼 → 팀 초대 발송
   └─ 수락/거절 버튼 → 초대 응답

2. "이 해커톤 팀 보기/생성" → /camp?hackathon=:slug 이동

3. 또는 메인 → "팀 찾기" → /camp 직접 접근
   └─ 팀 모집글 생성 (해커톤 연결 선택)
   └─ 관심 팀 연락처 확인
```

### 흐름 C: 결과물 제출 → 리더보드

```
1. 해커톤 상세 → [제출] 탭 진입
   └─ 제출 가이드 확인

2. (handover 해커톤의 경우)
   ├─ Step 1: 기획서 입력 (텍스트 또는 URL) → "저장"
   ├─ Step 2: 최종 웹링크 입력 (URL) → "저장"
   └─ Step 3: 솔루션 PDF 업로드 → "저장"

   (aimers 해커톤의 경우)
   └─ zip 파일 업로드 + 메모(optional) → "저장"

3. "제출" 버튼 클릭 → 제출 확정
   ├─ 제출 상태: "제출됨" 표시
   └─ 리더보드에 엔트리 자동 추가

4. [리더보드] 탭에서 순위 확인
   └─ 미제출 팀은 "미제출" 표기, 순위 없음
```

### 흐름 D: 랭킹 확인

```
1. 메인페이지 → "랭킹 보기" 큰 카드 버튼 클릭

2. /rankings 진입
   └─ 글로벌 랭킹 테이블 (rank / 닉네임 / points)
   └─ (옵션) 기간 필터로 범위 조정
```

### 3종 상태 처리 (모든 데이터 영역 공통)

| 상태 | 화면 처리 |
|---|---|
| **로딩중…** | 스피너 또는 스켈레톤 UI + "로딩중…" 텍스트 |
| **데이터 없음** | 상황에 맞는 안내 메시지 + 행동 유도 (예: "첫 팀을 만들어보세요!") |
| **에러** | 에러 메시지 + 재시도 버튼 또는 새로고침 안내 |

### 기타 예외 상황

| 상황 | 화면 처리 |
|---|---|
| **존재하지 않는 slug** | 404 페이지 + 메인으로 돌아가기 버튼 |
| **제출 필드 누락** | 필수 필드 하이라이트 + 인라인 에러 메시지 |
| **localStorage 접근 불가** | "데이터를 불러올 수 없습니다" 에러 배너 + 새로고침 안내 |
